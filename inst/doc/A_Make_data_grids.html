1. Make source data grids

library(BOMcatchr)

This example shows how to build the required data file, plot date that the file variables were built and then update it.

Make netCDF file

This example shows the steps required to build the netCDF data grid file.

First, let’s define the dates for the data grids. Here the data grids are created for data between the dates and . If the latter two dates were not input then data would be downloaded from 1/1/1900 to yesterday.

Note, in practice users often run once to build the netCDF data file that contain all variables over the entire record length (which requires ~5GB disk storage) and then use the netCDF grids for multiple projects, rather than re-building the netCDF grids for each project.

startDate <- as.Date(Sys.Date()-25,"%Y-%m-%d")
endDate <- as.Date(Sys.Date()-5,"%Y-%m-%d")

Next the file name for the netCDF grids need to be defined. Here we’ll just use a temporary file. You should change this to a non-temporary file name and folder.

ncdfFilename <- tempfile(fileext='.nc')

Now we’re ready to download and build the netCDF grids.

The netCDF data file contains grids of daily rainfall, minimum and maximum temperature. Below, this will be updated to include vapour pressure and solar radiation for all of Australia. The returned variable is a data.frames giving the success / fail for each variable where 1 denotes success and <0 an error.

status <- grid_build(ncdfFilename=ncdfFilename,
                updateFrom=startDate,
                updateTo=endDate,
                vars = c('precip','tmin','tmax'))
#> ... Testing downloading of each variable.
#>     Testing precip grid data.
#>     Testing tmin grid data.
#>     Testing tmax grid data.
#> ... Checking updateFrom and updateTo dates.

#>        - Existing variables to modify: (none)

The number of weather stations used to grid each time step

Plot source data dates and required data updates

The BoM gridded data undergoes a detailed review and update process (see https://www.bom.gov.au/climate/austmaps/about-rain-maps.shtml and https://www.bom.gov.au/climate/austmaps/update-schedule.shtml ). Hence, the netCDF grids that one may have built some time ago may be require updating with revised BoM data.

To understand when each variable and time-step was built, and which needs updating, the netCDF data can be examined against the above BoM update schedules - see for details. The plot below shows the date each time-step of each variable was created. The output from reports if any variables can be updated. Note, the input is ONLY used for testing and should not be input during regular use. Here today is set to 12 days into the future.

summary.ages <- BOMcatchr::grid_ages(ncdfFilename,
                                     today = Sys.Date()+12,
                                     plot.sourcedate = T)
#> Summary of source grid update dates for each variable:
#>     precip : 2026-09-10
#>     tmin : 2026-09-10
#>     tmax : 2026-09-10

Plot the number of weather stations used to make grids

The number of weather stations used to create each grid changes over time, which can provide a measure of grid reliability. We can extract the number of stations per variable as follows:

nstations <- BOMcatchr::extract_nstations(ncdfFilename)

Now let’s plot the number of stations over time.

 nvars = length(nstations)
 par(mfrow=c(nvars,1), mar =  c(5, 7.5, 4, 2.7) + 0.1)

 for (i in 1:nvars) {
    xdata = nstations[[i]]$Date
    ydata = nstations[[i]]$n_stations

    plot(xdata,
         ydata,
         main = names(nstations)[i],
         ylab = 'Number stations',
         xlab = 'Date',
         type='l')
 }

Add a variable to existing data grids

Because the date range of the new variable equals the date range of the existing variables, only vapour pressure data is updated. Optimised performance of grid build and extractions

To optimise the grid build and extract time, trials were undertake using a range of netCDF spatial and temporal chunk size. Only daily precipitation data was examined and for all days of 2020. Each combination of spatial and temporal chunk size was repeated ten times. The right column below shows the mean build time, extraction time and total time. The right column shows the speed up relative to using the default chunk size of , which allows netCDF to decide on a default chunking strategy.

Overall the result show that the build time speed-up is about equal to the default when the spatial chunks are 20 grid cells or greater and the time chunks are five days or less. More importantly, these settings result in an extract time over 110 times faster than the default. The package default chunk size is hence .

# Create plot using the interaction of both groups
plot_res <- function(data, doBuild=F, doExtract=F, doTotal=F, asSpeedup=F, doLegend=F) {

  data_null = subset(data, data$t == -999)
  data = subset(data, data$t != -999)
  groups <- unique(data$x)
  colors <- palette.colors(length(groups))

  if (doBuild){
    yname = 'build'
    ylbl = 'Build'
  } else if (doExtract) {
    yname = 'extract'
    ylbl = 'Extract'
  } else if (doTotal) {
    yname = 'total'
    ylbl = 'Total'
  }


  if (asSpeedup) {
    ylbl = paste(ylbl, "time speed-up")
    data[, yname] = mean(data_null[, yname]) / data[, yname]
  } else {
    ylbl = paste(ylbl, "time [sec/year]")
  }

  plot(data$t, data[, yname],
       type = "n",
       xlab = "Time dimesion chunk [days]",
       ylab = ylbl)
  for (i in seq_along(groups)) {
    sub_data <- subset(data, data$x == groups[i])

    sub_data <-  aggregate(as.formula(paste(yname, '~ t')), data = sub_data, FUN = mean)

    lines(sub_data$t, sub_data[, yname], col = colors[i], type = "b", pch = 16)
  }
  if (doLegend)
    legend("topright", legend = groups, col = colors, lty = 1, pch = 16, title = 'Spatial chunk [cells]')
}
